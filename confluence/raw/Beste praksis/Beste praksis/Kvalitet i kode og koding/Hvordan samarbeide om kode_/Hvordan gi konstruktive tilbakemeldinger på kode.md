
# Hvordan gi konstruktive tilbakemeldinger på kode

Status: <mark style="background: #baf3db;">I BRUK</mark>

Tilbakemeldinger på kode bør fokusere på læring og forbedring, ikke på personlig kritikk. Det er flere måter å gjøre dette på:

- **Start med det positive**: Begynn alltid tilbakemeldingen med å påpeke det som fungerer bra. Dette bygger selvtillit og skaper en mer mottakelig atmosfære for forbedringsforslag.
- **Vær konkret og spesifikk**: Unngå generelle kommentarer som "dårlig kode". Istedenfor bør du forklare nøyaktig hvilke forbedringer som kan gjøres, som for eksempel "Denne funksjonen kan optimaliseres ved å bruke feks en “lister”.
- **Fokuser på koden, ikke personen**: Tilbakemeldingen bør alltid handle om koden, ikke utvikleren. Kommenter på selve implementeringen og ikke personens kompetanse.
- **Gi forslag til forbedring**: Tilby mulige løsninger eller alternative måter å skrive koden på. Dette gjør tilbakemeldingen mer konstruktiv og lærerik.

### Hvordan ta imot tilbakemeldinger på kode

Å motta tilbakemeldinger, enten fra kollegaer eller verktøy, er en viktig del av læringsprosessen:

- **Se tilbakemeldinger som læringsmuligheter**: I stedet for å se tilbakemeldinger som kritikk, bør du betrakte dem som en sjanse til å lære og forbedre deg. Hvert innspill er en mulighet til å bli en bedre programmerer.
- **Unngå forsvarsposisjon**: Det kan være lett å føle seg angrepet når noen påpeker feil i koden din, men prøv å unngå å forsvare deg umiddelbart. Lytt aktivt, og vurder tilbakemeldingene før du responderer.
- **Spør om avklaring**: Hvis noe i tilbakemeldingen er uklart, ikke nøl med å be om en nærmere forklaring. Det er viktig å forstå hva som foreslås, slik at du kan lære og gjøre forbedringer.
- **Bruk verktøy aktivt**: Mange verktøy som linters og statisk analyseprogrammer kan gi verdifulle tilbakemeldinger. Se på dem som hjelpere som kan bidra til å forbedre koden din, og lær av anbefalingene deres.
